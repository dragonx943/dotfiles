## What this repo is

A personal dotfiles collection (no build system, package manifest, or test suite). Each top-level
directory is a self-contained config for one tool/app, mirroring the layout it expects relative to
`$HOME` (e.g. `fish/.config/fish/...` → `~/.config/fish/...`, `vim/.vimrc` → `~/.vimrc`). There is no
install/stow script in the repo; configs are expected to be symlinked or copied into place manually.

The repo currently spans two eras of setup:
- **Active (macOS)**: `fish/`, `kitty/`, `nvim/`, `vsnvim/`, `git_config/`, `jupyter/`, `tmux/`, `vim/`,
  `emacs/`, `ranger/`, `joshuto/`, `zathura/`, `shell/`. These are what the README and recent commit
  history focus on.
- **Legacy (Linux i3 rice)**: `awesomewm/`, `alacritty/`, `compton/`, `dunst/`, `i3/`, `i3blocks/`,
  `nitrogen/`, `optimus-manager/`, `picom/`, `polybar/`, `rofi/`, `xresources/`, `gtk3/`. Kept for
  reference; not actively developed.

There's no cross-tool code to "build" — changes are edits to individual config files. Verifying a
change means understanding the target application's config format (fish script, Lua, Vimscript,
TOML/INI, etc.), not running a test suite.

## Neovim config (`nvim/.config/nvim`)

Lua config using [lazy.nvim](https://github.com/folke/lazy.nvim) as the plugin manager.

- `init.lua` — entry point, requires `core.options` and `core.lazy`.
- `lua/core/` — non-plugin setup: `options.lua` (vim options), `keymaps.lua` (global keymaps),
  `lazy.lua` (bootstraps lazy.nvim and loads everything under `lua/plugins/`).
- `lua/plugins/` — one file per plugin, each returning a lazy.nvim plugin spec table. Adding a plugin
  means adding a new file here (or another entry in an existing spec) rather than editing a central list.
- `lua/helpers/` — small shared utilities imported by plugin specs (e.g. `colorscheme.lua`,
  `keys.lua`, `buffers.lua`).
- `lazy-lock.json` is the plugin version lockfile — don't hand-edit it; it's regenerated by lazy.nvim.

## Fish config (`fish/.config/fish`)

- `config.fish` — main entry point (aliases, env vars, abbreviations, sourcing).
- `conf.d/` — files here are auto-sourced by fish on startup (e.g. keybindings, theme, fzf setup).
- `functions/` — one fish function per file, filename must match the function name (fish autoload
  convention). Many `_fzf_*` functions implement custom fzf-driven widgets (history search, git log/status
  search, directory search, etc.) wired together by `fzf_configure_bindings.fish`.
- `completions/` — custom/vendored completion scripts for tools (`bun`, `copilot`, `fisher`, fzf key
  binding helpers).
- `fish_variables` is fish's own serialized universal-variable state, not something to hand-edit.
